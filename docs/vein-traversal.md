# Vein traversal

## Purpose

Mine a connected ore excursion without Lua recursion and return to its exact tunnel checkpoint through the same cleared cells.

The `OreCandidateQueue` helper holds discovered ore coordinates for one floor main-shaft cell. Stairs descent does not scan ore. `MainTunnelScan.scanCell` checks the four adjacent faces, collects classified coordinates without digging them, verifies that scan restored the exact committed cell pose and facing, then drains the queue synchronously before the shaft advances. The coordinator derives each adjacent direction from the anchor and runs the existing same-turtle vein entry/unwind path. A candidate is never removed by the discovery pass.

## Implemented behavior

`VeinTraversal.run(checkpoint, ops, seedInverse, qualifies, onMined, saveState)` performs iterative depth-first search with a coordinate-key visited set, a 64-block cap, and an 8-edge Manhattan-depth cap from the tunnel checkpoint. The caller has already dug and entered the seed ore; its move inverse is passed as `seedInverse` and is the first breadcrumb. It explores four forward headings plus up and down. Every discovered block adds an inverse movement and entry-facing breadcrumb. Child completion and abort unwind by popping breadcrumbs; failed inverse movement reports `VEIN_RETURN_BLOCKED`, and completion verifies checkpoint coordinates and facing. Inventory pressure stops discovery and unwinds before returning `INVENTORY_RETURN`.

The active coordinator in `src/branch_miner.lua` supplies policy-aware movement and turn callbacks, inspect/dig callbacks, inventory-pressure checks, route-fuel admission, and a cap-report callback. The directional safe-dig helpers return typed result tables, so the coordinator adapts `outcome.ok` to the literal boolean required by `VeinTraversal`; this preserves the reference routine's boolean dig contract while keeping the current typed safety outcomes. Before digging or entering the seed it saves an `entering` record with the checkpoint and expected adjacent entry pose. Seed entry and each outward or inverse movement retain the durable pending action until the matching DFS snapshot is ready; `Checkpoint.commitVeinAction` then writes pose, known route, frontier/breadcrumb state, and pending-action clearing in one snapshot. The traversal persists the shrinking inverse route while unwinding, then atomically clears the excursion on the final inverse move at the exact checkpoint. Each adjacent inspected block independently passes through `OreClassifier.isOre` from `src/mining/ore_classifier.lua`; qualifying neighboring IDs join the same connected vein, while non-ore neighbors are not dug. The optional `beforeDiscover()` callback can request an immediate unwind before any new neighbor inspection; this lets the caller honor an already-pending return request even when no ore is exposed. Before digging any candidate, traversal also invokes optional `canContinue(target)`. A denied or unavailable known-route-plus-reserve budget unwinds and returns `VEIN_FUEL_RETURN`; the active coordinator converts that result to `RETURN_REQUIRED`, so it stops at the exact tunnel checkpoint rather than continuing to the next work unit. When either vein cap is exhausted, traversal reports a warning only after unwind restores the exact checkpoint; the successful result lets the tunnel caller continue. A failed unwind returns an error and suppresses the report, so the caller stops. After reboot, the recovery classifier accepts multi-edge active and unwinding snapshots only when their visited coordinates, frontier/breadcrumb counts, facing sequence, checkpoint, and every known-route edge prove the full inverse walk; `miner resume` then executes only that unwind. Ambiguous `entering` records remain refused.

For veins entered from a main-shaft scan, the coordinator calls `MainShaftBackfill.seal` after successful unwind and before inventory service or shaft travel. It places cobblestone only in the exposed face at the saved checkpoint (forward for a wall scan, up, or down), then inspects that face and requires `minecraft:cobblestone`. Hidden vein cavities remain open. Missing cobblestone or any placement/verification failure stops the scan. This path does not yet protect a working cobblestone reserve; reserve policy is a separate unchecked plan item.

Inventory pressure and failed route-fuel admission both stop further vein discovery and unwind the inverse breadcrumbs before returning a typed outcome. The coordinator can start inventory service only after `INVENTORY_RETURN` confirms the exact checkpoint; `VEIN_FUEL_RETURN` becomes `RETURN_REQUIRED` at that same checkpoint. Any failed inverse move, including back, up, or down, returns fatal `VEIN_RETURN_BLOCKED`, so callers stop without home travel or continued shaft work.

Return-path movement failures are propagated after the shared adapter attempts bounded clearing of the planned target cell: vein inverse breadcrumbs stop with `VEIN_RETURN_BLOCKED`; branch return failures stop the branch; and `safeBack()` reports failure when its fallback turn or movement fails. Pose and known-route edges remain committed only by movement wrappers after the turtle API succeeds.

## Public entry points

- `require("src.mining.ore_candidate_queue")`; `OreCandidateQueue.new(checkpoint)` returns a slice-local queue with `add(candidate)`, `size()`, and `drain(currentPose, execute)`.
- `require("src.mining.vein_traversal")`
- `VeinTraversal.unwindSaved(vein, ops, saveState)` resumes an admitted active/unwinding excursion only by exact inverse-route unwind; it returns `{ok, code, blocks}` and saves before starting plus after each committed inverse.
- `require("src.mining.main_shaft_backfill")`; `MainShaftBackfill.seal(checkpoint, direction, ops)` seals one exposed face and returns a typed `{ok, code}` outcome.
- `VeinTraversal.run(checkpoint, ops, seedInverse, qualifies, onMined, saveState)` returns `{ok, code, blocks}`. Callbacks are `pose`, `project(direction)`, `inspect(direction)`, `dig(direction)`, `move(direction)`, `inventoryPressure()`, optional `turn(direction)`, optional `canContinue(target)`, `beforeDiscover()`, and `reportCap(blocks, maxBlocks, maxRadius)`. Active runtime must provide `turn` and `canContinue`; the legacy `turnRight()` fallback exists for isolated callers. `saveState(snapshot)` must return literal `true`; it receives stage `active` or `unwinding`, and receives `nil` only after exact unwind. A failed save stops the traversal with `VEIN_STATE_WRITE_FAILED`. A denied `canContinue` result stops discovery and unwinds with `VEIN_FUEL_RETURN`; the cap callback runs only after successful exact-checkpoint unwind.
- The coordinator's inspect callback returns the classifier result as its ore flag; it does not require equality with the seed ID.
- Physical action callbacks must report literal `true` on success. `project` returns the candidate world pose; the traversal commits visited coordinates only after movement succeeds.

## Invariants and assumptions

- Queue candidates are copied and de-duplicated by integer world coordinate. Drain requires exact anchor coordinates and facing, executes in discovery order, and clears only after every vein succeeds; a mismatch or failure retains queued work.
- The caller has already entered the seed ore block; `checkpoint` is the exact tunnel pose before that entry, and `seedInverse` reverses the seed movement.
- Horizontal movement is always performed after orienting the turtle through checked right turns. Breadcrumbs retain the entry facing so abort unwinds can restore the correct heading before moving back.
- The active movement wrappers enforce the current known-route fuel policy and update `pos` only on successful turtle movement.
- The traversal owns local frontier, visited, and breadcrumb tables for one synchronous excursion and passes defensive snapshots to the persistence callback. `Checkpoint.setVein` stores a validated `{stage, checkpoint, visited, frontier, route, blocks}` record, while the entering record also stores the expected adjacent `entryPose`. Successful vein moves combine their pose/route and DFS snapshot commits; a crash before this write leaves the pending action durable and therefore uncertain. Recovery admits only a fully validated unwind; it does not restart ore discovery after reboot.
- Once the optional pre-discovery callback requests unwind, no neighbor inspection, dig, or outward move occurs.
- Every active vein movement and turn uses the same intent/commit and fuel-aware coordinator callbacks as ordinary route movement. Before each candidate dig, the proposed route edge must leave enough fuel for the known route home plus reserve.

## Dependencies and limitations

- The per-cell queue is synchronous and in-memory. A crash before a candidate is dug may cause that cell to be scanned again; once the vein entry intent is persisted, existing vein recovery rules apply and ambiguous entry remains fail-closed. This does not add candidate queue data to the durable snapshot because no physical candidate action occurs before drain.
The module depends only on callback behavior supplied by its caller. The coordinator's physical movement callbacks persist action intent and enforce known-route fuel admission; the traversal's next state snapshot atomically commits the resulting pose and clears that intent. The pre-dig fuel callback prevents an outward candidate from consuming the return reserve. Turns still have their own intent/pose commit and the resulting frontier update is saved immediately afterward. A failed outward movement after digging stops with `VEIN_MOVE_FAILED` and does not fabricate a pose. Recovery only admits saved shapes for which the classifier proves every inverse direction, facing, visited coordinate, and known route to checkpoint; unsupported or malformed excursions remain fail-closed. Ambiguous seed-entry snapshots also remain refused.

## Verification

`tests/vein_traversal.lua` also injects a failed movement at every inverse
position in a mixed saved route. Each case verifies fatal `VEIN_RETURN_BLOCKED`,
no later inverse call, and durable retention of the failed and remaining route.

`tests/ore_candidate_queue.lua` verifies checkpoint gating, stable order, coordinate de-duplication, successful clear, and fail-closed retention.

`tests/vein_traversal.lua` covers persisted active/unwinding snapshots, restart unwind save ordering, exact checkpoint/orientation, fail-closed inverse failure, clear-on-return, save failure, a connected two-ID qualifying vein and a connected non-ore boundary, DFS completion, cap handling, fuel and inventory unwind, outward failure, and failed inverse `back`, `up`, and `down` movements. Its 14-slot pressure case uses `src.inventory.pressure` with the configured default and confirms no neighbor inspection or dig occurs before exact unwind. `tests/persistence_state.lua` covers entering records, atomic edge commits, pending-intent preservation on write failure, and atomic final checkpoint/vein clearing. `tests/persistence_recovery.lua` covers active/unwinding admission and ambiguous entering refusal. Run from the repository root with the project's Lua runtime.
